## 与 `../multiview/`（水平视角那套）的关系

两套**互补**，各自能独立喂给 Tripo，也可以只挑其中一套用：

| | 水平套 `../multiview/` | 俯视套（本目录） |
|---|---|---|
| 俯角 | 8~10°（近似立面） | **75°（高俯视）** |
| 提供的信息 | 腿型、裙板分层、饰条、整体高度比例 | 台面完整平面、**真实 2:1 长宽比**、袋口方位、六腿落点 |
| 生成方式 | 前视 + 左视，各水平镜像出一张 | 长边俯视 + 短边俯视，各水平镜像出一张 |

## 为什么是 75°（上一版 48° 错在哪）

台呢是**水平面**，俯拍时纵深方向被压缩，压缩量是 `sin(仰角)`：

```
台呢在画面上的高 = 真实纵深 × sin(仰角)
俯视投影的宽高比 = 2 / sin(仰角)      （正视，真实长宽比 2:1）
```

| 仰角 | 正视宽高比 | 侧视宽高比 | 相对真实 2:1 的偏差 | 腿投影 |
|---|---|---|---|---|
| 48°（上一版） | 2.69 : 1 | 0.67 : 1 | **+34.6%** | 535 mm |
| 60° | 2.31 : 1 | 0.58 : 1 | +15.5% | 400 mm |
| 70° | 2.13 : 1 | 0.53 : 1 | +6.4% | 274 mm |
| **75°（本版）** | **2.07 : 1** | **0.52 : 1** | **+3.5%** | 207 mm |
| 90° | 2.00 : 1 | 0.50 : 1 | 0 % | 0（腿全被顶框遮住） |

⚠️ **只有接近正俯视，画面里才是 2:1**。上一版取了 48°，正视被压成 2.69:1、侧视被拉成 0.67:1，两张一对比就像两张不同的桌子 —— 这是「长宽比看着不对」的全部原因。而且**低俯角比高俯角更糟**（30° 时是 4:1），所以修正方向只能是往上抬。

⚠️ 上一版 README 写的「42°」是用 `cos` 反解的，实际仰角是 48°，两者互为余角。**反解一律用 `sin`**，见下面的公式。

## 技术规格（四张完全一致）

| 项 | 值 |
|---|---|
| 尺寸 | 1024 × 1024 PNG，RGB，纯白 `#FFFFFF` 背景，无地面、无投影、无水印 |
| 俯角 | **75.0°**（四张统一） |
| 比例尺 | front/back 外框 880 × 418 px，left/right 外框 492 × 675 px（同一 px/mm，横向一致） |
| 台呢宽高比 | front/back **2.067**、left/right **0.513**（75° 理论值 2.071 / 0.518） |
| 投影 | 近正交、平行投影倾向，长轴与画面水平边平行，左右严格对称 |
| 镜像关系 | `back` = `front` **水平镜像**；`right` = `left` **水平镜像** |

⚠️ 俯视套的镜像关系与水平套**不是一回事**：俯视相机绕到桌子对面时，相机 up 向量会跟着反转，而桌子关于长轴、短轴都对称，正确变换是**水平镜像**。用「旋转 180°」会让桌腿朝上飘（已实测踩过并修正）。

## 对齐做法（重跑时按这个来）

生成图既拿不到 75°，也带透视。用 `_align-to-75deg.py` 做**分段纵向重投影**：

```
台呢是水平面    -> 纵深投影 ∝ sin(仰角)  => 台呢段纵向 × A
框侧 / 桌腿是竖直面 -> 投影高度 ∝ cos(仰角)  => 框腿段纵向 × B
分界线 = 台呢近端底边（那里正好是绿→木的强边缘，接缝被掩盖）
```

实测两张原图（透视图，台呢呈梯形，**比例尺取上底与下底的平均宽**，只取底边会把角度算高、只取顶边会算低）：

| 源图 | 台呢 上底 / 下底 / 高 | 平均宽高比 | 纵深误差 | A | B |
|---|---|---|---|---|---|
| front | 618 / 737 / 354 | 1.914 | AI 多画深 **4.5%** | 0.9243 | 0.5145 |
| left | 230 / 386 / 689 | 0.447 | AI 多画深 **11.9%** | 0.8636 | 0.2787 |

⚠️ **B 保留了 AI 原有的夸张幅度（约 1.36 倍），没有硬压到几何理论值。** 硬压（B≈0.40）的结果是近端木框被压成一条线、六条腿缩成小方块，反而不像桌腿 —— 试过，看图就废。1.36 是 AI 画腿相对 `800×cos(仰角)` 的平均放大倍数，保留它，腿还能辨认出是棱锥。

⚠️ 抗锯齿白边：`transform` 后边缘会有半透明灰边，`fit_canvas()` 里重新贴到纯白画布解决。

## 结构约定（模型只负责这些）

- **6 条腿**：4 角 + 2 长边中点，倒收分六角棱柱、大块钻石斜切面、方套箍 + 短圆柱脚圈，全香槟银阳极氧化铝
- **顶框**：深浓缩胡桃木，内沿香槟银细饰条，顶面白色菱形瞄准点
- **裙板**：深胡桃木 + 宽幅哑光银铝饰条 + 转角斜切银块
- **台面**：一整块封闭平板，**无袋口、无开孔、无凸起** —— 6 个袋口仍由程序化 / Blender 布尔挖洞，不进 AI 模型
- **桌下**：完全敞开

## 已知与理想状态的差异

1. **残余透视**：两张生成图都不是正交投影，台呢呈梯形（正视上底比下底窄 16%、侧视窄 40%）。分段重投影只改纵向，左边这个梯形留着 —— 表现为长边两侧的木框看着像斜条、远端框比近端薄。试过「parallel projection」「技术插图」「远端与近端必须等宽」三种写法压它，都无效；Tripo 的训练输入本来就是透视产品照，四视图会联合估计，影响有限。
2. **腿偏短**：75° 下 800 mm 高的桌子只投影出 207 mm，再乘 1.36 的夸张系数是 281 mm。画面里腿只剩「小墩子」，落点比腿型更可读 —— 腿型信息由水平套负责。
3. **腿型差异**：正视的腿偏米银、块面更大；侧视的腿偏冷银、棱面更碎。
4. **短边俯视的台面在画面里占比更大**：同一比例尺下，left/right 是 492×675、front/back 是 880×418，侧视必然更高更长，不是重复出错。
5. 四张里 `front`/`back` 视觉上几乎相同，`left`/`right` 也几乎相同 —— 俯视一个双轴对称物体的固有性质，两组的区别在细节（饰条高光、腿的遮挡关系）。

## 如果还要更干净

75° 是「比例」和「腿的可见性」的折中。如果只想要绝对精确的 2:1，可以做 **90° 正俯视**：台呢严格 2.00:1 / 0.50:1，四张严格互为旋转 90°，透视也几乎消失；代价是桌腿完全被顶框遮住，图里只剩矩形台面 + 6 个袋口位 —— 纯平面图，体积信息全交给水平套。
