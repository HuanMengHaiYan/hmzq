# 第二轮 Tripo GLB 模型诊断（4 个模型）

> 分析对象：`07e0e072…` / `16b2e6b7…` / `8e4d0af3…` / `acddc615…`.glb  
> 方法：GLB 二进制解析（结构 + 顶点级）+ 三视角渲染（等轴 / 俯视 / 正视）+ 顶面栅格占用检测。  
> 证据图：`GLB诊断-等轴.png` / `GLB诊断-俯视.png` / `GLB诊断-正视.png`

---

## 结论速览

**这 4 个模型目前都不能直接进游戏**，不是"打磨一下"的问题，而是有三项硬缺口：

1. **袋口一个都没开孔** —— 台面 90~99% 是实心平面，6 个袋口位置全是凸起的装饰圆钮。球没有地方掉下去。
2. **纯白模，没有材质也没有 UV** —— 0 贴图、0 图片、`TEXCOORD` 不存在、单一材质 `{"name":"material"}` 连颜色都没有。就算形状对了，贴不上任何贴图，游戏里是一坨灰。
3. **全身焊成一张网格** —— 1 node / 1 mesh / 1 primitive / 1 material，台布、木框、腿、袋口全部连在一起，没有材质槽也没法分件。

进步是有的：模型 2、3 的台面比第一轮干净（不再有对角线三角切分），木框层次与袋口装饰比第一轮丰富，整体轮廓更像台球桌。**但第一轮最致命的三件事（真开孔 / 腿型 / 现代风格）零进展。**

## 一、结构层（GLB 元数据，4 个完全一致）

| 项目                      | 实测                                        | 期望 / 影响                                                       |
| ----------------------- | ----------------------------------------- | ------------------------------------------------------------- |
| generator               | `Beijing VAST-…-AIGC Content`             | 确认 Tripo 原生导出                                                 |
| node / mesh / primitive | **1 / 1 / 1**                             | 无法分件、无法分材质槽                                                   |
| material                | **1 个，内容 `{"name":"material"}`**          | 连 `baseColorFactor` 都没有                                       |
| texture / image         | **0 / 0**                                 | 纯几何白模                                                         |
| vertex attributes       | **仅 `POSITION` + `NORMAL`**               | ⚠️ **没有 `TEXCOORD_0`**，补贴图前必须重新 UV 展开；也没有 `TANGENT`，法线贴图同样上不了 |
| indices                 | `UNSIGNED_INT`，`mode: 4`（三角）              | 不是四边面                                                         |
| 三角面 / 顶点                | 19,179~~20,251 / 10,412~~11,040           | 整桌 2 万面偏低，袋口/饰条这类曲面细节会糊                                       |
| 文件 / BIN                | 470~493 KB，几乎全是几何                         | 印证没有贴图数据                                                      |
| extensions              | `KHR_materials_volume`、`FB_ngon_encoding` | Tripo 的 n-gon 编码；配合「四边面 / P1.0」导出时容易拿到**不带贴图**的几何             |

> **这一层不是提示词的问题，是导出设置的问题。** 需要在 Tripo 里选带 PBR / Texture 的 GLB 导出（而不是 geometry / quad-only），并确认导出结果里 `images ≥ 1`、`TEXCOORD_0` 存在。否则再换十版提示词也还是白模。

**另外两个接入时会踩的坑**

- **朝向不一致**：模型 2 的长轴在 **Z**，其余三个在 **X**。导入时要单独给模型 2 转 90°，不能四个用同一套变换。
- **归一化尺度不一致**：4 个都把最长边归一到 1，但长宽比从 1.44 到 1.72 各不相同，缩放时不能只用一个系数，必须按各自包围盒分别校准到 2.82 × 1.55 m。

**一个需要纠偏的判断**：上一轮我诊断的「台面被切成三角拼块」，从这次的栅格占用看，模型 0 顶面 **98.9% 连续覆盖** —— 台面其实是**连续实心**的，那些对角线是**共面网格的拓扑接缝**（线框渲染把它画出来了），不是真的裂成几块。贴材质后如果法线一致，线可能看不见；但 AI 生成的网格法线常有微小偏差，会出现明暗三角。这个问题**可修**（焊接顶点 + 重算法线），优先级远低于「袋口没洞」和「白模」。我上一轮把它排得太重了。

## 四、根因判断

### ① 中文提示词的硬约束很可能没有被解析

上一版中文提示词里明确写了「**绝对不要车削罗马柱、圆雕花柱、兽爪脚、卷草纹**」，负向词也逐条列了「车削罗马柱 / 维多利亚 / 古董」。结果**四个模型 100% 都是车削罗马柱古董台** —— 这不是随机偏差，是约束整段失效。

两种可能：这轮生成没用上中文提示词；或者 Tripo 对中文负面标签的抑制远弱于英文（长串中文逗号词表很可能被当成一整个短语处理，而不是 N 个独立抑制标签）。**中文解决了字数，但可能引入了语义损失。**

### ② 更根本的：这不是提示词能解决的问题

Text-to-3D 生成的是「看起来像」的闭合曲面，**让 AI 在一张网格里挖出 6 个尺寸精确到 114/127mm、位置精确的贯通孔，基本超出当前方法的能力**。四轮结果一致印证：它只会把袋口做成凸起的装饰件。再加多少「贯通的洞」的描述也难改。

### ③ 导出档位不对

`FB_ngon_encoding` + 单材质 + 零贴图，很像选了「四边面 / P1.0 / 几何优先」的导出。我上一版文档里建议开 Quad Mesh、优先 P1.0 —— 如果这个建议导致拿到白模，这部分是我的锅，下一版要改成「几何用 P1.0，但贴图与材质必须单独一份带 PBR 的 GLB 导出」。

## 五、下一步（按收益排序）

1. 换导出设置：重新导出一份带 P`BR 贴图的 GLB，验收标准写死 —— images ≥ 1、材质里有 baseColorTexture、顶点属性里有 TEXCOORD_0。白模版本留着做几何参考即可。`
2. `改中英混排提示词：中文承载信息密度，但关键负面标签必须用英文原词（antique, Victorian, turned baluster legs, raised pocket caps, diagonal seam），正向风格锚点也用英文（modern Chinese 8-ball championship table）。给一份 ≤1000 字符的混排版。`
3. `放弃让 AI 做袋口：走「桌体外壳由 Tripo 出（木框 / 银饰条 / 腿 / 袋口皮套）」+「台布、库边、6 个精确袋口由程序化或 Blender 布尔挖洞生成」的拼合方案。这仍是整桌全新 3D 模型，且进袋判定与碰撞的物理基准不丢。`
4. `桌腿拆件单独生成：单独生成一条「银色倒棱锥多棱柱腿」再实例化 6 份 —— 四轮里腿型从没对过，把它从整桌里摘出来成功率最高。`
5. `走 Image-to-3D 用目标图：中式八球台那套银腿 + 白饰条 + 皮袋口用文字描述四轮都没还原出来，图片参考是当前最可能突破的路径。`
6. `模型定稿后再动代码：真实规格（6 腿 / 800mm 桌高 / 40mm 库边 / 中袋 127mm）会连带 TABLE.legH、cushionH、台布色、相机机位与开球参数重扫，见 v2 提示词文档第六节。`

## 附：本次分析的复现方法

- `GLB` 头 12 字节 + chunk 遍历拿 JSON / BIN；直接读 `POSITION` float 三元组求真实范围（**不要只信 accessor.min/max 的元数据**）。
- 三视角渲染：three.js 0.185 + `GLTFLoader`，4 个模型统一居中并把最长边缩到 2.0，`MeshStandardMaterial` 灰模 + `EdgesGeometry(32°)` 叠线框，等轴 / 俯视 / 正视相机固定。
- 顶面栅格：筛选「三顶点 Y > 0.72×maxY」的水平三角形，投影到长轴×短轴 72×36 栅格做点内判断，再检查 6 个袋口预期位置的占用率。
