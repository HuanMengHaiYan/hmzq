# 移动端性能分析报告（红米 K30）

分析日期：2026-09-17 · 代码版本 **v0.5.0**（移动端适配 + 画质设置 + 阴影按需刷新）
目标：**最低不低于 30fps，理想 60fps（60Hz 屏封顶）**
目标机型：**红米 K30（8GB 内存）** —— 本报告按**最差情况**（4G 版骁龙 730G / Adreno 618）推算，
若你的是 K30 5G（骁龙 765G / Adreno 620）则整体再快约 30~40%。

---

## 一、结论速览

| 项目 | 结论 |
|---|---|
| 默认画质（手机上「自动」= 阴影 1024² + 渲染 1.25× + 纹理 4×） | ✅ **及格**，命中 30fps 底线 |
| 开球瞬间（16 球同时运动） | ⚠️ 30–45 fps，**卡在底线附近** |
| 玩十几分钟热降频后 | ⚠️ 30–45 fps |
| 想稳 60 | 做不到；「流畅」档可到 45–60 |
| 物理引擎 | ✅ 完全不是瓶颈（0.3–0.8ms） |

**一句话**：v0.5.0 起手机上默认就走"降一档"的画质（阴影减半 + 分辨率降 1.6 倍像素 + 阴影按需刷新），
**不用额外设置就能守住 30fps**；真机上用左上角面板的**帧率**读数自查，掉到 30 以下就往「流畅」调一档。

## 二、硬件基线（红米 K30，按最差情况）

| 项目 | 值 |
|---|---|
| SoC | 骁龙 730G：2×A76@2.2G + 6×A55@1.8G（若为 K30 5G 则是 765G） |
| GPU | **Adreno 618** ≈ 骁龙 865（Adreno 650）的 **40%** |
| 屏幕 | 6.67" IPS，**1080×2400，395 ppi，60Hz** |
| devicePixelRatio | 约 **2.75**（1080px / 393dp）；横屏 CSS 视口约 **873 × 393** |
| 系统 WebView | 随 MIUI 更新，WebGL2 可用 |
| 散热 | 中低端机长时间负载降频明显（约 70% 性能） |

> 本机的 `devicePixelRatio` 是 2.75，也就是说**按 CSS 像素渲染会明显发糊**（395ppi 下 1 CSS px = 1 物理 px 太粗），
> 所以画质里的渲染分辨率是**按 CSS 像素的倍数**给的（DPR 上限）：低 = 100%、中 = 125%、高 = 200%，
> 也就是"每 CSS 像素渲染几个物理像素"。

## 四、v0.5.0 新增的画质设置

设置位置：**启动器 → 游戏设置 → 画质**，或**游戏内 ⚙ 设置 → 画质**（共用一份，改动即时生效）。
存储键 `hmzq.quality.v1`，默认 `preset: auto`。

### 四个档位 + 一个「自定义」

画质面板是**一档 + 四个细分项**：档位 `自动 / 低 / 中 / 高 / 自定义`，
选**自定义**才展开**阴影精度 / 渲染分辨率 / 贴图精度 / 纹理细节**四行。下表是各档背后的实际取值：

| 档位 | 阴影 | 渲染分辨率（DPR 上限） | 纹理（各向异性） | 桌面贴图 | 用途 |
|---|---|---|---|---|---|
| **自动** | 桌面 = 高；**触摸设备 = 中** | | | | 默认 |
| **低** | 关（省 100% 阴影填充） | 100% | 1× | 512² | 弱机 / 追求帧率 |
| **中** | 1024² | 125% | 4× | 1024² | 手机上推荐 |
| **高** | 2048² | 200% | 8× | 2048² | 桌面观感 |
| **自定义** | 逐项自己选 | | | | 想抠细节时用 |

- **换档位会把四项一起刷成该档的值** —— 所以「高 → 自定义」是从高档起步微调，不会跳回出厂默认。
- **改任一细分项 → 档位自动落到「自定义」**。
- 四项细分值任何时候都留着，切走再切回来还在。

（阴影填充量按边长² 变化：2048²→1024² 省 **75%**；渲染像素总数按倍数² 变化：200%→125% 省 **61%**。）

### 另外两个默认开启的降级

| 措施 | 说明 |
|---|---|
| **阴影按需刷新** | shadow map 只跟灯与投影物体有关、跟相机无关。世界静止（球与球杆都不动）时**不再重画**，静止帧省掉整个 shadow pass。球在动 / 杆在动 / 蓄力时自动恢复刷新 |
| **纹理各向异性跟随画质** | 建纹理时就用设置里的级别，改设置时统一重上传 |

### "自动"为什么这样定

- 桌面（Electron / 鼠标键鼠）→ **高** = 2048² + 2× + 8×：与 v0.4.0 完全一致，**桌面上一个像素都不降**。
- 触摸设备 → **中** = 1024² + 1× + 4×：像素量降到 25%、阴影填充降到 25%，而 395ppi 屏上肉眼几乎看不出差别。
- 需要更省就手动选 **低**（阴影全关 + 0.75× + 1×），帧率优先。

## 五、帧率估算（红米 K30 / Adreno 618）

按 v0.4.0 的实测基线（Adreno 650 上待机 52–90fps、开球 30–38fps）折算：Adreno 618 ≈ 650 的 40%，
但 v0.5.0 把像素量降到 39%、阴影降到 25%，两者基本抵掉，再叠加 WebView 的 0.7–0.8 折。

| 场景 | 均衡（手机默认） | 流畅 | 高清 |
|---|---|---|---|
| 待机 / 瞄准（球静止，阴影不重画） | **45–60 fps** ✅ | **55–60 fps** ✅ | 20–30 fps ❌ |
| 正常击球 | **38–52 fps** ✅ | **50–60 fps** ✅ | 18–26 fps ❌ |
| 开球瞬间 | **30–42 fps** ⚠️ | **40–52 fps** ✅ | 12–20 fps ❌ |
| 降频后（玩 15 分钟） | **30–45 fps** ⚠️ | **38–50 fps** ✅ | 10–16 fps ❌ |

> ⚠️ = 贴线，可能偶发掉到 30 以下；建议真机跑一轮确认，不满意就选「流畅」。
> 高清档在 K30 上**不要用**（那是给桌面的档位），这也是「自动」在触摸设备上不选它的原因。

## 六、还能再快的话，优先级排序

| 优先级 | 措施 | 预期收益 | 状态 |
|---|---|---|---|
| 🥇 | 阴影：降精度 / 按需刷新 | 静止帧 −20~30% | ✅ **已落地（画质设置）** |
| 🥈 | 渲染分辨率（档位里的 DPR 上限） | 200% → 125%，像素 −61% | ✅ **已落地（画质档位）** |
| 🥉 | **合并台桌静态网格**：48 个台桌 mesh 按材质合并成 3–5 个（`BufferGeometryUtils.mergeGeometries`） | draw call 132 → 约 20，省 4–8ms（**手机上最值得做的下一项**） | ⏳ 未做 |
| 4 | 减一盏灯（去掉 DirectionalLight fill） | 每像素少一个光照计算 | ⏳ 未做 |
| 5 | 球体分段 32×24 → 24×16 | 三角形少约 30%，但 29k 本来就不多 | ⏳ 未做 |
| 6 | 阴影换成贴地假阴影贴片 | 彻底去掉 shadow pass，但质感下降 | ⏳ 备选 |

## 七、真机怎么读数据

1. **游戏内左上角面板的「帧率」**：半秒平均的真实读数（v0.5.0 新增）。开一杆、看开球那几秒的数值。
2. **画质面板底部那行**：显示当前实际生效的 `阴影 / 渲染像素 / 各向异性`，方便对照上报。
3. Chrome 远程调试：`chrome://inspect` → 连上手机 → Performance 面板录一段开球。
4. 建议测三轮：① 默认（自动）打 5 分钟 → ② 流畅档打 5 分钟 → ③ 连续玩 20 分钟后回到默认再测（看热降频）。
   把三组帧率发我，就能定最终的默认档位。

## 九、已知未知项（必须真机验证）

1. **机型实际是 730G 还是 765G**：本报告按更差的 730G 估算；若是 5G 版，余量会明显更宽松。
2. **WebView 版本差异**：不同 MIUI 版本的系统 WebView 性能差别很大。
3. **热降频曲线**：只有连续玩 20 分钟才测得准。
4. **首屏耗时**：3.49MB JS（gzip 1.26MB，含内联 wasm）+ 解码，预估 **1.5–2.5 秒**。
5. **音频合成开销**：开球瞬间十几个振荡器同时起振，估算 < 0.5ms，暂不担心。
